## 1. 包与运行形态

| 项 | 值 |
|---|---|
| npm 包名 | `@deepseek-ai/dsh-auto-continue` |
| 插件形态 | Cordis `Service` 子类，默认导出 |
| 服务名 | `ctx.quota` |
| 事件 | `quota/changed` |
| 依赖基线 | DSH `0.1.5-rc.2` 系列（见 `package.json`；升级前读 `doc/记录/DSH-0.1.5-升级影响评估.md`） |
| 发布形态 | 独立发布，不加入 `dsh-base`；提供补丁 overlay |

**单包同时承载 host 与 client**（`src/` 与 `src/client/`）。这是刻意的：DSH 的 client module 系统
只扫描 **host loader 条目**的 `package.json` 来发现 client bundle，第三方独立插件必须 host + client
同包声明 `dsh.client`（第一方 monorepo 才拆成独立 client 包）。

## 2. 模块结构与职责

```
src/
  index.ts             # QuotaRuntime（Service）：装配、监听器、设置接入、自建路由
  config.ts            # 配置 schema、跨字段校验、解析辅助
  state.ts             # 实例运行时状态与纯函数（相位、episode、退避序列、时间解析）
  platform.ts          # 平台模板接口、统一快照、耗尽判定
  platforms/index.ts   # 内置平台模板清单
  platforms/zenmux.ts  # ZenMux 平台模板实现
  recovery.ts          # 统计查询退避、可取消等待、等待决策
  notice.ts            # 重发提示消息的模板渲染与构造
  wire.ts              # 自建路由的 JSON 读写与错误信封
  trust-fence.ts       # 自建路由的来源校验（DNS-rebinding / 跨站防御）
  client/              # 浏览器侧设置选项卡
    index.tsx / AutoContinueSection.tsx / InstanceCard.tsx / edit-state.ts / api.ts / locales.ts
```

职责边界（改动时必须维持）：

- **纯逻辑**放 `state.ts` / `platform.ts` / `recovery.ts` 的纯函数里，便于单测；
  **I/O 与编排**放 `index.ts`。
- **平台专属知识只允许出现在 `platforms/`**：通用模块（配置、状态、恢复、界面）中不得出现
  任何具体平台的名称、默认端点、字段名或专属判断。
- client 侧的**可测逻辑**（编辑态映射、纯函数）与 React 组件分离，前者有单测。

## 3. 对外服务与事件

### 3.1 `ctx.quota` 服务

| 成员 | 用途 |
|---|---|
| `status(instanceId)` | 取某实例的当前状态快照 |
| `isDisabled(instanceId)` | 该实例是否已放弃自动续跑 |
| `statusForProvider(providerId)` | 调试便利方法：按 provider 查其绑定实例的状态 |
| `platforms()` | 已注册平台模板的元信息（`{ id, label }[]`，按 id 排序）；界面平台下拉的数据源 |
| `registerPlatformAdapter(adapter)` | **注册平台模板**，返回注销函数；第三方接入新平台的唯一入口 |

### 3.2 状态快照

```ts
type QuotaInstanceState =
  | { phase: 'unconfigured' }                          // 未配置凭据
  | { phase: 'idle' }                                  // 正常，无进行中的恢复
  | { phase: 'checking-stats' }                        // 正在查询配额接口
  | { phase: 'waiting-reset'; resetAt: number }        // 等待配额重置
  | { phase: 'post-reset-retrying'; attempts: number } // 重置后宽容重试中
  | { phase: 'disabled' }                              // 已放弃
```

### 3.3 事件

```ts
'quota/changed'(instanceId: string, state: QuotaInstanceState, affectedProviders: string[]): void
```

按实例发布；payload 携带实例 id、新状态与受影响的 provider 列表。未来「切换 provider」的策略
插件可监听本事件（本插件不实现切换）。

## 4. 与宿主框架的集成点

全部通过公开扩展点，不修改 DSH 其他包：

| 集成点 | 用途 | 约束 |
|---|---|---|
| `ctx.on('agent/request-error', …)` | 拦截请求失败、决定是否续跑 | waterfall 语义：本插件负责的错误短路（不调用 `next()`）；其他错误必须 `next()` |
| `ctx.on('session/event', …)` | 观察 `assistant/message`，据此把实例复位为 `idle` | 只读观察，不改变会话事件 |
| `ctx.settings.installSection(...)`（经 `ctx.inject(['settings'])`） | 注册设置命名空间，接入统一设置分层 | 必须用 `settings` 服务注入后再注册 |
| `ctx.webServer.register(...)` | 自建 `/auto-continue/api` 路由，供界面读写设置 | 必须做来源校验（trust-fence），并沿用统一错误信封 |
| `ctx.inject(['webServer'])`、`webRuntime.trustedHosts` | 取受信 Host 列表 | 路由不可绕过校验 |
| `ctx.credentials.resolve(...)` / launch environment | 解析凭据引用 | 解析失败即视为无可用的凭据 |

由框架侧提供的其他事实：`agent/request-error` 的 payload 含 provider、failure、turn/step 与
本轮中止信号；`ctx.sessions.fork` 在 open turn 期间会被拒绝（见需求 NFR-10）。

## 5. 依赖与版本

- 运行时依赖：`@deepseek-ai/schemastery`、`@deepseek-ai/dsh-launch-environment`、
  `@deepseek-ai/dsh-llm`；其余为 peer / type 依赖。
- 版本区间必须覆盖当前基线（注意 semver 的 prerelease 规则：旧区间覆盖不到新 prerelease）。
- 升级 DSH 前先读 `doc/记录/DSH-0.1.5-升级影响评估.md`，并跑通全套测试与真实挂载端到端测试。
