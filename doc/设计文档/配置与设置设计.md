# 配置与设置设计

> 性质：设计文档（描述**当前**字段、默认值与通道；随版本演进）
> 需求来源：`doc/需求文档/需求文档.md` FR-9、NFR-4 ~ NFR-6
> 相关：`doc/设计文档/架构与集成设计.md`（集成点）、`doc/设计文档/平台适配器设计.md`（`type` 指向的模板）

---

## 1. 配置分层

每个设置命名空间（本插件为 `auto-continue`）的值按以下顺序解析：

1. **schema 默认值**；
2. **base 层**：插件在 `cordis.yml` 中的 `config`；
3. **user 层**：用户在界面中的修改（持久化到 `settings.yaml`）。

界面只写 user 层；界面上的「删除」实际是清除 user 层覆盖，清除后会露出 base 层。因此：

- 默认 `platformInstances: {}`、`providerBindings: {}`——所有实例由用户在界面新建，从而全部落在
  user 层，界面可以真正增删改。
- 高级用户若在 `cordis.yml` 预置实例，界面无法真正删除它，只能清除用户覆盖（该场景不特殊展示）。

---

## 2. 顶层字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `platformBaseURL` | string | `""` | **历史兜底覆盖**：非空时对所有实例生效，优先级低于实例级 `baseURL`、高于平台模板默认端点。新配置建议留空 |

---

## 3. 实例（`platformInstances`，map，默认 `{}`）

键为实例 id，须匹配 `^[a-z][a-z0-9-]*$`（小写字母开头，仅小写字母、数字、连字符）。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `type` | string | **必填** | 平台模板标识（已注册模板的 `platform`）。不再默认成某个具体平台 |
| `baseURL` | string | 无 | 实例级端点覆盖；留空用模板默认端点 |
| `options` | object | `{}` | 平台专属参数；结构由所选模板声明并校验 |
| `managementKeyRef` | string | 无 | 凭据引用（环境变量名／凭据存储引用）；界面不展示 |
| `managementKey` | string | 无 | 明文凭据；标记为 secret，界面不回显 |
| `resumeNotice.enabled` | boolean | `false` | 是否在重发前注入提示 |
| `resumeNotice.template` | string | 见下 | 提示模板，支持 `{provider}`、`{hours}`、`{minutes}` |
| `statsRetry.initialDelayMs` | number | `60000` | 配额接口失败后首次退避 |
| `statsRetry.maxDelayMs` | number | `900000` | 单次退避上限 |
| `statsRetry.totalTimeoutMs` | number | `3600000` | 退避总时长上限 |
| `postResetRetry.delaysMs` | number[] | `[60000,120000,240000,480000,900000]` | 宽容重试等待序列；数组长度即最大重试次数 |
| `resetBufferMs` | number | `5000` | 等待重置时刻的缓冲，规避窗口切换竞态 |

`resumeNotice.template` 默认值：
`"因额度限制，本次请求等待了 {hours} 小时 {minutes} 分钟后重新发送。"`

> 单次查询请求超时不是可配置字段，而是固定常量（30s）——它属于实现细节，见
> `doc/设计文档/恢复流程设计.md` §3。

### 3.1 示例

```yaml
- id: auto-continue
  name: '@deepseek-ai/dsh-auto-continue'
  config:
    platformInstances:
      zenmux-main:
        type: zenmux
        managementKeyRef: ZENMUX_MANAGEMENT_API_KEY
        # baseURL: https://proxy.internal     # 可选：覆盖模板默认端点
        # options: {}                         # 可选：平台专属参数
        resumeNotice:
          enabled: false
          template: "因额度限制，本次请求等待了 {hours} 小时 {minutes} 分钟后重新发送。"
        statsRetry:
          initialDelayMs: 60000
          maxDelayMs: 900000
          totalTimeoutMs: 3600000
        postResetRetry:
          delaysMs: [60000, 120000, 240000, 480000, 900000]
        resetBufferMs: 5000
    providerBindings:
      zenmux-provider: zenmux-main
```

## 4. Provider 绑定（`providerBindings`，map，默认 `{}`）

- 键：provider-id（宿主框架的 LLM 路由名）；值：实例 id。
- 一个 provider 只能绑定一个实例；一个实例可被多个 provider 绑定。
- 值指向不存在的实例 → 配置校验失败。
- 未出现在绑定表中的 provider：插件不介入，行为与未安装时一致。

---

## 5. 跨字段校验（fail loud）

| 规则 | 生效时机 |
|---|---|
| 实例 id 匹配 `^[a-z][a-z0-9-]*$` | 加载期、设置写入期 |
| `type` 为已注册模板 | 加载期**告警**（允许模板后注册）、设置写入期**报错** |
| `managementKeyRef` 与 `managementKey` 不同时非空 | 加载期、设置写入期 |
| `baseURL` 若非空须为 http(s) | 加载期、设置写入期 |
| `options` 为普通对象，并通过模板声明的参数校验 | 加载期、设置写入期（模板未注册时跳过） |
| `providerBindings` 的值指向存在的实例 | 加载期、设置写入期 |
| `statsRetry` 三字段为正整数 | 加载期、设置写入期 |
| `postResetRetry.delaysMs` 非空正整数数组 | 加载期、设置写入期 |
| `resetBufferMs` 为非负整数 | 加载期、设置写入期 |

> 「未知平台类型」在加载期只告警、在写入期报错，是刻意的分层：平台模板可能由稍后加载的插件
> 注册，配置文件需要能够提前声明；而写入设置时所有插件都已加载完，必须严格。
> 结构性规则（id、数值、互斥等）在**任何**时机都直接报错，不受该放宽影响。

## 6. 凭据解析与安全

- 解析顺序：`managementKey`（明文）优先；否则用 `managementKeyRef` 经凭据服务解析，
  无凭据服务时回退到 launch environment。
- 解析不到 → 该实例视为未配置凭据，不参与续跑。
- `managementKey` 标记为 secret：设置描述符与线路响应中**不回显**；日志与事件中不得出现明文。
- 界面留空 = 不修改：写入设置前，从当前值回注已有 secret。

---

## 7. 设置读写通道

- **设置服务**：经 `ctx.inject(['settings'])` 后注册本插件的设置命名空间，`cordis.yml` 的 config
  作为 base 层。
- **自建路由**：`/auto-continue/api`（前缀路由），提供：

  | 方法 | 用途 |
  |---|---|
  | `settings.get` | 读取脱敏后的设置值与「是否已配置凭据」标记 |
  | `settings.update` | 整体替换实例与绑定（写入前回注未回传的 secret） |
  | `providers.list` | 可供绑定的 provider 列表 |
  | `platforms.list` | 已注册平台模板元信息（界面平台下拉的数据源） |

- 不走 DSH 内置的 settings RPC：其命名空间白名单不服务第三方插件。
- 安全要求：必须做来源校验（受信 Host / 同源），非受信请求返回 403；只接受 POST；
  统一使用成功／错误信封；未知方法返回 404。

## 8. 设置界面

- **位置**：设置面板中的**独立顶层选项卡**「自动续跑 / Auto Continue」（与 General / Models /
  Plugins 并列，而非嵌在 Plugins 页里）。
- **布局**：实例卡片列表 —— 卡片标题为实例 id，副标题为平台展示名，徽标显示凭据状态与提示状态；
  展开即编辑；底部为「新增」按钮；删除走确认弹窗（若仍绑定 provider，确认文案提示将同时解绑）。
- **表单字段**：实例 id（新建可编辑，已有只读）、平台（下拉，**数据来自 `platforms.list`**）、
  平台端点（可选）、平台专属参数（JSON，可选，留空等于无）、凭据（密码框，留空不修改）、
  提示开关与模板、统计退避三项、宽容重试序列（逗号分隔）、重置缓冲、provider 绑定多选。
- **绑定交互**：未绑定的 provider 可被任意实例勾选；已绑定的只在其绑定实例中可见、可取消；
  其他实例列表中隐藏（降低实现难度；后续可改为置灰）。
- **空状态**：无实例时提示点击「新增」。
- **不做**：不展示 `managementKeyRef`、不展示全局 `platformBaseURL`、不展示实例实时运行状态、
  不做凭据存储集成。

> 平台下拉与平台专属参数字段是**数据驱动**的：新增平台不需要改界面代码（见 NFR-7）。

---

## 9. 设置变更的生效语义

| 变更 | 生效时机 |
|---|---|
| 提示开关／模板 | 即时生效，下一次注入按新配置 |
| 统计退避、宽容重试序列、重置缓冲 | 对新开始的恢复过程生效；进行中的过程不中断 |
| 新增／删除实例、修改绑定 | 下一次配额耗尽判定时生效 |
| 删除实例 | 进行中的等待不中断；该实例下 provider 的新错误按删除后的绑定处理（无绑定则放行） |
| 修改凭据 | 下一次查询配额时生效 |

## 10. 历史配置（v1，已废弃）

v1 把平台信息与策略字段直接内嵌在 provider 下（`providers.<id>.platform`、全局 `resumeNotice` /
`statsRetry` / `postResetRetry` / `resetBufferMs` / `statsRequestTimeoutMs`）。v2 起改为
「平台实例 + 绑定」三层模型；v3 起实例 `type` 必填、新增实例级 `baseURL` 与 `options`、
全局 `platformBaseURL` 降级为历史兜底。迁移方式：把原 provider 条目改写为一个实例，
并用 `providerBindings` 绑定该 provider。
