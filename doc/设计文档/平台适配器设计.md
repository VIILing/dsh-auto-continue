# 平台适配器设计

> 性质：设计文档（描述**当前**接口与规格；签名与字段随版本演进）
> 需求来源：`doc/需求文档/需求文档.md` FR-1 / FR-2 / NFR-7 / NFR-8
> 设计思想与硬性要求：`doc/设计文档/平台模板设计约束.md`（本文是其接口契约的具体形态）

---

## 1. 职责

平台适配器（Platform 模板）承载**全部平台专属知识**：

1. 哪种失败属于本平台的「配额耗尽」；
2. 去哪查、怎么读本平台的配额状态；
3. 由配额状态算出「何时可以重试」。

通用层（恢复状态机、配置、界面、路由）只通过本接口与平台打交道，不认识任何具体平台。

## 2. 接口契约

```ts
interface PlatformQuotaAdapter {
  /** 平台模板标识（= 实例的 type）。必需。 */
  readonly platform: string

  // ── 以下为可选元数据，用于让模板自带身份与差异化能力 ──
  /** 界面展示名；缺省回退到 platform。 */
  readonly label?: string
  /** 该平台默认 API 端点；实例 baseURL 可覆盖，全局 platformBaseURL 为历史兜底。 */
  readonly defaultBaseURL?: string
  /** 平台专属参数（实例 options）的 schema；声明后写入设置时 fail loud 校验。 */
  readonly optionsSchema?: Schema<Record<string, unknown>>

  // ── 必需能力 ──
  /** 判断一次失败是否为本平台的「配额耗尽」。 */
  matchesQuotaExhausted(failure: LlmFailure): boolean
  /** 请求平台配额接口，返回统一快照。 */
  fetchQuota(context: QuotaFetchContext): Promise<PlatformQuotaSnapshot>
  /** 由快照算出「可重试时刻」（epoch ms）；算不出返回 null。 */
  resolveWaitTarget(snapshot: PlatformQuotaSnapshot): number | null

  // ── 可选能力 ──
  /** 覆盖通用「耗尽」口径（默认 usagePercentage >= 1 || remainingFlows <= 0）。 */
  isExhausted?(snapshot: PlatformQuotaSnapshot): boolean
}
```

查询上下文（模板能看到**全部**输入，也只能看到这些）：

```ts
interface QuotaFetchContext {
  readonly credential: string                        // 已解析的凭据
  readonly baseURL: string                           // 已解析的端点
  readonly instance: PlatformInstanceConfig          // 实例配置，平台专属参数在 instance.options
  readonly signal: AbortSignal                       // 取消信号（插件生命周期 + 单次请求超时）
}
```

契约要点（对应设计约束 §3.2）：

- **只实现必需项即可接入**；可选项用于表达差异，不得因为它们的增减而让通用层认识具体平台。
- 模板**不得**反向依赖插件内部结构、不得读写共享状态、不得假定被调用的时机与次数。
- 模板内部出错等同于「无法确定」，通用层据此走放弃路径；模板不得用编造数据诱导等待。

## 3. 统一快照

平台私有响应必须先被模板翻译成统一形状；通用层只处理这个形状。

```ts
interface PlatformQuotaSnapshot {
  windows: QuotaWindow[]      // 平台归一化后的配额窗口列表
}

interface QuotaWindow {
  name: string                // 窗口标识，如 '5h'、'7d'
  usagePercentage: number     // 0–1；不做 [0,1] 夹取
  remainingFlows: number      // 剩余额度
  resetsAt: string | null     // ISO 8601 或 null
}
```

**耗尽判定**：通用口径为 `usagePercentage >= 1 || remainingFlows <= 0`（**或**关系，不要求同时
满足）。平台若无法用该口径表达「用完」，实现可选的 `isExhausted` 覆盖之。

时间解析：`resetsAt` 用 `Date.parse` 解析，失败视为缺失；等待目标 = `resetsAt + 实例的缓冲时间`。

## 4. 判定链（通用层如何使用契约）

```
请求失败的 provider
  → providerBindings[provider]                        （未绑定 → 不处理，交回下游）
  → platformInstances[instanceId]
  → 实例无凭据 / 状态为 disabled → 不处理，交回下游
  → instance.type → 已注册模板
  → adapter.matchesQuotaExhausted(failure)            （不命中 → 交回下游）
  → 进入恢复流程
```

**识别职责归属于模板**：通用流程不得内置任何平台措辞；模板找不到时按「不处理」处理
（正常配置下配置校验会拦截）。

## 5. ZenMux 模板规格（首个内置模板）

- 标识：`zenmux`；展示名：`ZenMux`；默认端点：`https://zenmux.ai`。
- 配额接口：`GET {baseURL}/api/v1/management/subscription/detail`，
  请求头 `Authorization: Bearer <credential>`，超时取固定常量（30s）。
- 成功判定：HTTP 200 且响应 `success === true`；任何非 200、网络错误、超时、JSON 解析失败、
  字段缺失或类型错误，均视为**查询失败**。
- 字段映射：`data.quota_5_hour → 窗口 '5h'`、`data.quota_7_day → 窗口 '7d'`；
  窗口内的 `usage_percentage`、`remaining_flows`、`resets_at` 原样映射。

### 5.1 错误识别规则

只认订阅配额耗尽，**刻意不处理**余额类 402（`insufficient_credit` / `reject_no_credit`）：

1. `failure.message` 长度 > 10000 → 不命中；
2. `failure.status` 存在且不等于 402 → 不命中；
3. 命中任一文本规则即判定（`quote_exceeded`；`subscription quota limit/exhausted`；
   `reached your subscription quota limit`）；
4. 或命中 JSON 形态：`"code":"402"` 且 `"type":"quote_exceeded"`。

> 形态说明：上游会把错误压平，`failure.message` 可能是**人类可读文本**，也可能是**一段 JSON
> 字符串**（含转义引号）；识别逻辑必须同时覆盖。`quote_exceeded` 一项刻意区分大小写，
> 其余用于人类文案的规则忽略大小写。
>
> 不依赖 `failure.code`：上游对 ZenMux 402 的错误码映射不完整（`quote_exceeded` 可能未映射为
> `QUOTA`），也可能把 `insufficient_credit` 映射为 `QUOTA`。
>
> **已核对（需求 §7 验收第 18 条）**：`quote_exceeded` 用的是需求方提供的**线上抓取的真实 402
> 响应体**（逐字节保存在 `tests/fixtures/zenmux-402-quote-exceeded.json`，文案尾部带
> ` (request_id: …)`）；`insufficient_credit` / `reject_no_credit` 暂无线上样本，取自
> ZenMux 官方错误码参考
> （<https://zenmux.ai/docs/guide/advanced/error-codes>）。回归覆盖 JSON 原文、
> `dsh-llm-pi-ai` `formatProviderError` 压平的 `402: {json}`、以及 SDK 已把 body 折进
> `error.message` 的 `402 <message>` 形态——其中 `402: {json}` 已用真实 `dsh-llm-pi-ai` 的
> `normalizeProviderError` / `formatProviderError` 实测复现。**现有规则无需修订**即通过；
> 尾部 `request_id` 不影响识别。
> 回归用例见 `tests/platforms/zenmux.spec.ts`「黄金样本：真实 402 识别规则核对」。

### 5.2 等待目标规则

输入为归一化后的 `5h` / `7d` 两个窗口：

| 7d 状态 | 5h 状态 | 等待目标 |
|---|---|---|
| 未耗尽 | 已耗尽 | `5h` 的 `resetsAt` |
| 未耗尽 | 未耗尽（统计滞后） | `5h` 的 `resetsAt` |
| 已耗尽 | 已耗尽 | `max(5h.resetsAt, 7d.resetsAt)` |
| 已耗尽 | 未耗尽（理论不应出现，保守处理） | `7d` 的 `resetsAt` |

缺失处理：所需窗口或 `resetsAt` 为 null／解析失败 → 返回 null（通用层判为关键信息缺失，
当前请求正常失败）；`max(a, b)` 中一方为 null 时取另一方。

## 6. 注册、注销与校验时机

- **注册**：内置模板在 `platforms/index.ts` 的清单里追加一项；第三方模板在自己的插件中调用
  `ctx.quota.registerPlatformAdapter(adapter)`，不修改本插件任何文件。
- **注销**：注册返回注销函数；注销后该模板立即不再参与判定，且不影响其他模板。
- **校验时机（有意分层）**：
  - **加载期**：实例的结构性错误（id 格式、数值字段等）立即报错；但「模板尚未注册」只告警，
    允许配置文件先声明、平台插件后加载。未注册期间该实例不被处理，也不会导致插件启动失败。
  - **设置写入期**：此时所有插件已加载完，未知平台类型与平台专属参数非法都必须直接报错。
- **界面可见性**：`ctx.quota.platforms()` / 路由的 `platforms.list` 只暴露已注册模板，
  界面据此渲染平台下拉，因此**新增平台无需改动界面代码**。
